# itsxzh 个人站 v1

**Status:** ready-for-agent

## Problem Statement

作者目前没有一个固定的个人站点，潜在雇主、招聘者和同行开发者只能零散地看到 GitHub 等平台上的信息，无法在一个地方同时了解“我是谁、做过什么、写过什么”。同时，作者手上还没有真实项目和文章，不能等内容齐了再搭站，否则站点结构、内容模型和部署链路会一直拖延。

因此需要一个**内容优先、结构完整、可以先上线再填内容**的个人站：现在用明确标记的占位内容跑通全部页面，以后只替换内容文件，不需要重构。

## Solution

构建并部署一个中文个人站，地址为 `https://itsxzh99.github.io`，使用 Next.js App Router 静态导出，内容来自仓库中的 Markdown/MDX 文件。视觉采用 Notion 风格的暖白底、暖黑字、单栏排版，层次完全由字号和留白建立，不使用彩色模块、卡片或阴影。

v1 包含：首页、Project 列表与详情、Post 列表与详情、About、404，以及 RSS、sitemap、robots。首页先展示作者身份与社交链接，再展示精选 Project 和最新 Post。站点放入 3 个占位 Project 和 3 篇占位 Post，全部带 `placeholder` 标记；另放草稿夹具验证草稿不会公开。

v1 不做：真实内容撰写、CMS、评论、Analytics、搜索、标签页、归档页、分页、双语、自定义域名、动态 OG 图片、联系表单、邮件订阅。

## User Stories

### 访客：了解作者

1. 作为潜在雇主，我希望在首页立刻看到作者是谁、做什么，以便判断是否继续浏览。
2. 作为潜在雇主，我希望首页展示精选 Project，以便快速评估作者的作品。
3. 作为同行开发者，我希望看到作者的 GitHub、Email 和 RSS 入口，以便进一步联系或订阅。
4. 作为访客，我希望 About 页提供更完整的作者介绍，以便了解背景和方向。
5. 作为访客，我希望站点在手机、平板和桌面上都排版正常，以便在任何设备上阅读。
6. 作为访客，我希望页面加载快、阅读时不发生布局跳动，以便专注内容。
7. 作为访客，我希望可以在浅色和深色主题间切换，且默认跟随系统，以便选择舒适的阅读环境。
8. 作为使用屏幕阅读器的访客，我希望页面有清晰的语义结构和跳转到正文的入口，以便高效导航。
9. 作为键盘用户，我希望所有链接和按钮都有可见的焦点样式，以便知道当前焦点在哪里。
10. 作为访客，我希望能清楚识别占位内容，以免把示例误认为作者的真实作品。

### 访客：浏览 Project

11. 作为同行开发者，我希望在 `/projects/` 看到全部 Project 的列表，以便了解作者的作品全貌。
12. 作为同行开发者，我希望列表项显示标题、摘要、日期和示例标记，以便快速筛选感兴趣的内容。
13. 作为同行开发者，我希望点开 Project 后看到背景与目标、作者角色、技术栈、结果和相关链接，以便判断项目的真实性和作者贡献。
14. 作为同行开发者，我希望 Project 的相关链接能打开仓库或在线 demo，以便直接查看成果。
15. 作为同行开发者，我希望 Project 详情页的正文支持 Markdown/MDX 的标题、列表、链接和代码块，以便作者充分表达。

### 访客：阅读 Post

16. 作为读者，我希望在 `/writing/` 看到按发布时间倒序排列的 Post 列表，以便找到最新文章。
17. 作为读者，我希望列表项显示标题、摘要、日期、阅读时长和示例标记，以便判断是否值得打开。
18. 作为读者，我希望 Post 详情页有舒适的阅读宽度、中文行高和清晰的标题层级，以便长时间阅读。
19. 作为读者，我希望 Post 详情页显示发布日期、预计阅读时长和标签，以便了解文章背景。
20. 作为读者，我希望 Post 详情页提供目录，以便在长文中快速跳转。
21. 作为读者，我希望 Post 末尾有上一篇/下一篇，以便连续阅读。
22. 作为读者，我希望 Post 中的代码块有清晰的等宽字体和可读的底色，以便阅读技术内容。
23. 作为读者，我希望标签只作为信息展示、不链接到空页面，以免点进 404。
24. 作为读者，我希望文章不足 5 篇时首页自然少显示几篇，而不是出现空位或假内容。

### 访客：订阅与分享

25. 作为读者，我希望通过 `/rss.xml` 订阅全文 RSS，以便在新文章发布时直接阅读。
26. 作为读者，我希望 RSS 只包含已发布文章、不含草稿，以便订阅内容干净。
27. 作为读者，我希望分享链接时看到合理的标题和描述，以便判断链接内容。
28. 作为搜索引擎，我希望读取 `sitemap.xml` 和 `robots.txt`，以便正确索引公开页面。
29. 作为访客，我希望访问不存在的地址时看到友好的 404 页和返回首页入口，以便不被困住。

### 作者：维护内容

30. 作为作者，我希望新增一个 Project 只需创建一个 MDX 文件并填写 frontmatter，以便不修改代码。
31. 作为作者，我希望新增一篇 Post 使用同样的方式，以便发布流程一致。
32. 作为作者，我希望 frontmatter 缺字段或类型错误时构建失败并给出明确错误，以便尽早发现。
33. 作为作者，我希望草稿不出现在列表、详情页、RSS、sitemap 中，以便未完成的内容不会公开。
34. 作为作者，我希望用 `featured` 和 `order` 控制首页精选 Project，以便首页体现我的优先级。
35. 作为作者，我希望替换占位内容时只需删除 `placeholder` 标记，以便站点自然过渡到真实内容。
36. 作为作者，我希望项目与文章的 slug 来自文件名，以便不需要维护两份标识。
37. 作为作者，我希望站点名称、署名和社交链接在全站一致，以便品牌统一。
38. 作为作者，我希望推送 `main` 后由 GitHub Actions 自动构建和部署，以便无需手动发布。
39. 作为作者，我希望构建前自动跑端到端测试，以便坏掉的页面不会上线。
40. 作为作者，我希望仓库就是 GitHub Pages 用户页仓库，以便站点位于根域名。

## Implementation Decisions

### 技术栈与构建

- Next.js App Router + TypeScript（strict）+ npm。
- 使用静态导出，产物为纯静态文件，部署到 GitHub Pages。
- 开启 `trailingSlash`，保证 GitHub Pages 的目录式路由可直接访问。
- 图片使用非优化模式（静态导出不支持 Next.js 图片优化服务）。
- 样式使用 Tailwind CSS v4，设计 token 以 CSS 自定义属性集中定义；不引入组件库、UI 框架或 CSS-in-JS。
- 不加载 Web 字体，使用系统中英文字体栈，避免中文 Web 字体体积和闪烁。

### 内容模型

- Project 与 Post 均为 MDX 文件，分别放在两个内容目录中；文件名即 slug，frontmatter 不重复写 slug。
- 使用 `gray-matter` 解析 frontmatter，使用 `zod` 在构建时校验；任一文件不合法则构建失败，错误信息包含文件名和字段名。
- Project frontmatter 字段：`title`、`summary`、`date`（`YYYY-MM-DD`）、`role`、`stack`（字符串数组）、`links`（可含 `repo`、`demo`）、`cover`（可选）、`featured`（布尔）、`order`（数字）、`draft`（布尔）、`placeholder`（布尔）。
- Post frontmatter 字段：`title`、`summary`、`date`（`YYYY-MM-DD`）、`tags`（字符串数组）、`cover`（可选）、`draft`（布尔）、`placeholder`（布尔）。
- Post 按日期倒序；Project 先按 `order` 升序，再按日期倒序。
- `draft: true` 的内容不进入列表、详情页、RSS、sitemap，也不生成静态路由。
- `placeholder: true` 的内容正常公开，但详情页顶部显示中性提示条“示例内容，待替换”，列表项显示小号“示例”文字；替换真实内容时删除该字段。
- 日期以中文长格式显示（如“2026 年 11 月 10 日”）。
- 阅读时长按中文阅读速度计算：CJK 字符约 400 字/分钟，拉丁词约 200 词/分钟，向上取整，最少 1 分钟。
- 正文渲染支持标题、段落、列表、链接、引用、表格、行内代码、代码块；代码块使用语法高亮和浅暖灰底色。
- 标题自动生成锚点；Post 目录由二级和三级标题生成，放在正文之前，不做悬浮侧边栏。

### 路由与页面

- `/`：首页。
- `/projects/`：Project 列表。
- `/projects/[slug]/`：Project 详情。
- `/writing/`：Post 列表。
- `/writing/[slug]/`：Post 详情。
- `/about/`：About。
- `/404`：未找到页面。
- `/rss.xml`：全文 RSS。
- `/sitemap.xml`、`/robots.txt`：构建时生成。

### 页面结构

- 全站布局：顶部为站点名 `itsxzh` + 导航 `Projects` / `Writing` / `About` + 主题切换；主体单栏，最大宽度 720px；底部页脚为 `© 2026 itsxzh · RSS · GitHub`。
- 移动端三个导航链接保持横排，缩小间距和字号，不做汉堡菜单；页面不得出现横向滚动。
- 首页自上而下：一句话自我介绍与 tagline“开发者，写代码也写字” + GitHub / Email / RSS 图标 → 精选 Project（最多 3 个）→ 最新 Post（最多 5 篇，不足则显示实际数量）。
- Project 列表：每条显示标题、摘要、日期、技术栈摘要、示例标记；无封面图、无卡片边框。
- Project 详情：标题、摘要、日期；角色、技术栈、相关链接的元信息；“背景与目标”和“结果”由 MDX 正文表达；占位内容演示完整结构。
- Post 列表：每条显示标题、摘要、日期、阅读时长、标签、示例标记。
- Post 详情：标题、日期、阅读时长、标签；目录；MDX 正文；上一篇/下一篇。
- About：一段作者介绍、社交链接、当前关注方向；内容为静态页面，不走内容目录。
- 404：一句“页面不存在” + 返回首页链接。
- 空状态：列表为空时显示一句中性说明，不显示假数据。

### 视觉系统

| Token | 值 | 用途 |
| --- | --- | --- |
| 页面底色 | `#FAF9F7` | 暖白背景 |
| 正文色 | `#37352F` | 暖近黑 |
| 次要文字 | `#787774` | 日期、摘要、标签、页脚 |
| 分隔线 | `#E8E6E1` | 仅用于分隔线与表格 |
| 链接色 | `#2383E2` | 仅链接与 focus ring |
| 代码底色 | `#F1EFEA` | 行内代码与代码块 |
| 暗色底色 | `#191919` | 暗色模式背景 |
| 暗色正文 | `#D4D4D4` | 暗色模式正文 |
| 暗色链接 | `#529CCA` | 暗色模式链接 |

- 字号：h1 40px、h2 28px、h3 22px、正文 17px、辅助文字 14px。
- 行高：正文 1.8，标题 1.25–1.4。
- 间距：段落 20px，列表项 40px，章节 96px；移动端章节间距减半。
- 禁止卡片背景、阴影、圆角容器、彩色标签块、渐变装饰；标签用灰色 `#tag` 纯文字。
- 占位提示条不用黄色或警告色，使用小号次要文字 + 细分隔线。
- 暗色模式跟随系统，可手动切换并持久化；切换时禁用过渡以避免闪烁。

### 可访问性与细节

- 语义化 `header` / `nav` / `main` / `footer`，提供“跳到正文”链接。
- 当前导航项使用 `aria-current`；主题切换按钮有可读的 `aria-label`。
- 所有交互元素有 `:focus-visible` 样式；颜色对比度满足 WCAG AA。
- 尊重 `prefers-reduced-motion`；v1 只做轻微的颜色过渡，不做滚动动画。
- 封面图可选；有封面时必须提供替代文本。

### SEO 与订阅

- `metadataBase` 为 `https://itsxzh99.github.io`。
- 页面标题格式：首页为 `itsxzh — 开发者，写代码也写字`；其他页为 `页面名 · itsxzh`。
- 每页有 description（优先使用内容摘要）、canonical、OG 的 title/description/type/url/site_name、Twitter summary card。
- v1 不做动态 OG 图片，不引入 JSON-LD。
- RSS 输出最近 20 篇已发布 Post 的全文，语言 `zh-CN`，包含站点标题、描述和每篇的标题、链接、日期、摘要、正文 HTML。
- sitemap 包含所有公开静态页面和非草稿内容详情页；不包含 404。
- robots 允许全部抓取并指向 sitemap。

### 占位与草稿夹具

- 3 个占位 Project：覆盖“有 repo 链接”“有 demo 链接”“两者都有或都无”的差异；至少 1 个 `featured: true`，3 个都设为精选以填满首页，并用 `order` 控制顺序。
- 3 篇占位 Post：覆盖短摘要/长摘要、不同标签、不同日期，确保列表排序可验证。
- 额外放 1 个草稿 Project 和 1 篇草稿 Post 作为测试夹具，标题含“Draft fixture”，用于验证草稿完全不公开。
- 占位内容使用真实可信的中文示例，不出现 Lorem ipsum；所有占位项都带 `placeholder: true`。

### 部署

- GitHub 仓库改名为 `itsxzh99.github.io`，作为 GitHub Pages 用户页；本地目录名可保持 `xzh-site`。
- GitHub Actions 在 push 到 `main` 时执行：安装依赖 → 构建 → 运行端到端测试 → 上传静态产物 → 部署 GitHub Pages。
- 构建产物根目录放置 `.nojekyll`，避免 GitHub Pages 的 Jekyll 处理。
- 首次部署前需要用户确认仓库改名和远端配置；这是外部可见操作，不在实现阶段自动执行。

## Testing Decisions

- **一条接缝**：端到端测试，针对 `next build` 生成的真实静态站点，用 Playwright 以 Chromium 打开页面并断言用户可见行为。不写组件测试，不写内容解析单元测试。
- 好的测试只断言外部行为：URL、可见文字、链接目标、HTTP 响应、排序结果、页面是否出现；不断言 CSS 类名、组件名或内部函数。
- 构建时的 `zod` 校验负责 frontmatter 合法性；测试不重复验证字段类型。
- 覆盖范围：
  - 首页：身份、tagline、社交链接、精选 Project 的顺序、最新 Post 的数量与顺序、占位标记。
  - Project：列表数量与顺序、进入详情、标题/摘要/角色/技术栈/链接、占位提示条、MDX 标题渲染。
  - Post：列表倒序、进入详情、日期/阅读时长/标签/目录/上一篇下一篇、占位提示条。
  - About 与 404：内容存在、404 可返回首页。
  - RSS：`/rss.xml` 返回合法 XML，包含 3 篇已发布 Post 的全文，不包含草稿。
  - sitemap 与 robots：包含公开页面，不包含草稿和 404。
  - 草稿：两个草稿夹具不出现在任何列表、RSS、sitemap 中，其详情 URL 返回 404。
  - 主题：默认跟随系统；切换后 `html` 的 `data-theme` 变化并在刷新后保持；暗色下正文与背景对比可见。
  - 移动端：375px 宽度下导航横排、无横向滚动、正文可读。
  - SEO：首页与详情页的 `<title>`、description、canonical、OG 标签正确。
- 测试命令会先构建再启动静态服务器；CI 在部署前运行同一套测试。
- 无既有测试先例，这是仓库的第一套测试。

## Out of Scope

- 真实 Project 和 Post 的内容撰写与素材制作。
- CMS、在线编辑、数据库、服务端 API。
- 评论、Analytics、访问统计、埋点。
- 站内搜索、标签页、归档页、分页、相关文章、作者页。
- 中英双语或 i18n 路由。
- 自定义域名、HTTPS 证书配置、DNS。
- 动态 OG 图片、JSON-LD、结构化数据。
- 联系表单、邮件订阅、Newsletter。
- 视觉回归测试、跨浏览器矩阵（v1 只跑 Chromium）、性能预算测试。
- 复杂动效、页面过渡动画、滚动动画。
- RSS 分页、RSS 分类 feed。
- 封面图设计与图片优化管线。

## Further Notes

- 术语使用 `GLOSSARY.md` 的定义：Project、Post、Writing、Featured、Placeholder。
- 两个已记录的决策见 `docs/adr/0001-nextjs-static-export.md` 与 `docs/adr/0002-github-pages-user-site.md`。
- 这是作者的第一个个人站，实现时应优先选择简单、可读、少依赖的方案；不要为未来可能的需求提前抽象。
- 占位内容的目的不是“填充”，而是让导航、列表、详情、RSS、SEO 在真实构建中全部跑通；因此占位内容必须覆盖不同字段组合和排序场景。
- 仓库改名和首次部署是外部可见操作，执行前必须再次向作者确认。
